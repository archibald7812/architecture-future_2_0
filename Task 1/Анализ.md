# Анализ проблемных мест и приоритизация

## Проблемные места

| №  | Проблема                                                                   | Описание                                                                                             |
|----|-----------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------|
| 1  | Зависимость от API Gateway                                                 | Единая точка отказа – если шлюз падает, все домены будут недоступны.                                  |
| 2  | Сложность управления Data Mesh                                              | Необходимость координации множества распределённых доменных команд и контрактов данных.             |
| 3  | Производительность Data Lake                                                | Загрузка и трансформация больших объёмов данных может замедлять отчёты в BI.                         |
| 4  | Различные уровни зрелости доменных сервисов                                  | Некоторым командам не хватает экспертизы создания микросервисов и CICD.                               |
| 5  | Безопасность и разграничение доступа                                         | Контроль доступа к данным в распределённой системе требует сложной ABAC-реализации.                 |
| 6  | Совместимость с легаси-системами                                             | Переход во времени сохраняет старые DWH и Power BI – нужен мост для синхронизации.                    |

## Приоритизация (MoSCoW)

| Категория  | Проблемы                                                |
|------------|---------------------------------------------------------|
| **Must**   | 1, 5                                                    |
| **Should** | 3, 6                                                    |
| **Could**  | 2                                                       |
| **Won’t**  | 4 (в рамках первого этапа, обучение планируется позже) |

- **Must** (обязательно): устранить единый точку отказа (API Gateway) и внедрить разграничение доступа.  
- **Should** (желательно): оптимизировать производительность Data Lake и обеспечить мост к легаси‑источникам.  
- **Could** (можно): начать планирование и пилоты Data Mesh governance.  
- **Won’t** (не будем делать сейчас): полномасштабное обучение всех команд микросервисам (отложить во 2-м квартале).
